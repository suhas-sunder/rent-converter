Reviewed 2026-11-13 using pinned Playwright 1.58.2 and Chromium 145.0.7632.6. This reviewer authored the W03/W04 feature implementations; these are direct browser/visual observations, **not independent-of-author sign-off**. No application code changed during this review.

## Date-focus assertion: native picker is a real visible focus stop

The host-only computed-style assertion produced a false positive for W03 `deadline-next-payday` / `deadline-due-date` and W04 `schedule-start-date`.

Actual keyboard traversal on the assembled local application at `http://127.0.0.1:3029` found four Tab stops within each native date control. The first three select month, day and year: each selected segment is visibly blue and the host has a solid 2px sky-colored outline. At the fourth stop, the native calendar icon has a clearly visible black rectangular focus border. At that stop `document.activeElement` is still the date input, but the host matches `:focus-within` while neither `:focus` nor `:focus-visible` matches. The host reports no outline or shadow because focus is on the native internal picker button.

The reviewer opened all three picker-focus screenshots and their preceding selected-year screenshots. Both W03 dates and the W04 lease-start date show visible focus; no CSS repair was warranted. The first three segment states were also directly checked on the final W03/W04 immutable previews.

Root narrowed the harness exception to `input[type=date] && !matches(':focus') && matches(':focus-within')`, retaining computed outline/ring checks for ordinary date segments and other fields, and capturing screenshots of the native picker stop. This is an evidence-backed exception to a host-style heuristic, not a blanket exclusion of date inputs or an assertion of screen-reader speech/native-picker behavior in every browser.

### Zoom evidence limitation and follow-up

The original `*-zoom200.png` images were produced by CSS `zoom:2` at a fixed 720px CSS viewport. W03 visibly compresses its columns in that stress test. It is not native browser zoom: the media-query viewport remains 720px while the available painted width is reduced. The parent has replaced this acceptance method with `chrome.tabs.setZoom(2)` in an isolated Chromium profile.

The new native-zoom state checks report the expected halved CSS viewport, devicePixelRatio 2 and CSS zoom 1. However, the initial full-page native-zoom PNGs are cropped to the CSS width while retaining doubled painted pixels (visibly cutting the right half of W03/W04). These initial captures are insufficient for visual zoom sign-off. This screenshot-capture limitation was reported to the parent; corrected physical-viewport captures were reviewed subsequently, as recorded below. It is not evidence of application overflow, and no application repair is justified from the cropped capture alone.

The three final hosted close-ups were also individually opened: `artifacts/final/w03-deadline-next-payday-native-picker-focus.png`, `w03-deadline-due-date-native-picker-focus.png`, and `w04-schedule-start-date-native-picker-focus.png`.
